# FoodCall — Direction artistique & description des pages

## 1. Objectif du document

Ce document décrit la direction artistique globale du site FoodCall, les règles visuelles à respecter, les composants récurrents, ainsi que les pages présentes dans le prototype actuel.

FoodCall est une application web sociale et géolocalisée permettant de découvrir des restaurants, publier des avis, créer des groupes, lancer des votes et recommander des restaurants via un système de “calls”.

L’objectif de la direction artistique est de donner au produit une identité moderne, claire, sociale et crédible, tout en gardant une dimension ludique liée à la food et aux décisions de groupe.

---

# 2. Identité globale du produit

## 2.1 Positionnement

FoodCall doit être perçu comme une application :

- moderne ;
- sociale ;
- simple à comprendre ;
- orientée décision rapide ;
- crédible pour un usage quotidien ;
- suffisamment ludique pour encourager la contribution communautaire.

Le site ne doit pas ressembler à une simple marketplace de restaurants. Il doit mettre en avant la prise de décision collective, la réputation des utilisateurs et la pertinence des recommandations.

## 2.2 Ton visuel

La DA globale repose sur un équilibre entre :

- une interface premium et propre ;
- une ambiance chaleureuse liée à la nourriture ;
- des éléments sociaux visibles ;
- des statistiques et scores faciles à lire ;
- une gamification légère via niveaux, badges, classements et scores.

Le rendu doit rester professionnel. Les éléments ludiques doivent soutenir l’expérience utilisateur sans rendre l’interface enfantine.

# 3. Règles de direction artistique

## 3.1 Format général

Les maquettes actuelles sont conçues pour un format desktop 16:9.

Règles à respecter :

- largeur desktop large ;
- composition en dashboard ;
- navigation supérieure fixe ou visuellement persistante ;
- structure en colonnes ;
- cartes arrondies ;
- forte hiérarchie visuelle ;
- beaucoup d’espace blanc ;
- densité d’information élevée mais lisible.

## 3.2 Couleurs

### Couleur principale

Orange FoodCall : utilisé pour les actions principales, les onglets actifs, les scores importants, les barres de progression, les icônes principales et les éléments de validation visuelle.

Usages principaux :

- boutons primaires ;
- underline de l’onglet actif ;
- pictogrammes importants ;
- badges actifs ;
- scores positifs ;
- barres de vote ;
- indicateurs de progression.

### Couleurs secondaires

Blanc et gris très clair : utilisés pour le fond général, les cartes et les séparateurs.

Noir / charbon : utilisé pour les titres, les noms de restaurants, les noms d’utilisateurs et les informations principales.

Gris moyen : utilisé pour les textes secondaires, les métadonnées, les dates, les descriptions et les informations moins prioritaires.

Vert : réservé aux états positifs comme “retenu”, “validé”, “en cours” ou “activé”.

Rouge / orange foncé : peut être utilisé pour les alertes douces, les scores faibles ou les badges “non retenu”, sans être agressif.

## 3.3 Typographie

La typographie doit rester moderne, sans-serif, lisible et proche d’un produit SaaS premium.

Hiérarchie recommandée :

- titres hero : très grands, gras, impactants ;
- titres de cartes : gras, taille moyenne ;
- labels et métadonnées : petits, gris, lisibles ;
- chiffres clés : grands, gras, très contrastés ;
- actions secondaires : orange, taille réduite, mais facilement repérables.

Le texte doit rester court, clair et orienté action.

## 3.4 Formes et cartes

L’interface repose fortement sur des cartes blanches avec :

- coins très arrondis ;
- ombres légères ;
- bordures gris très clair ;
- padding généreux ;
- séparation interne subtile.

Les cartes doivent structurer l’information sans donner une sensation de blocs lourds.

## 3.5 Iconographie

Les icônes doivent être simples, linéaires ou semi-remplies, cohérentes entre elles.

Types d’icônes récurrents :

- localisation ;
- restaurant / couverts ;
- groupe ;
- avis ;
- téléphone / call ;
- étoile ;
- cœur ;
- notification ;
- partage ;
- réglages ;
- badge / trophée ;
- commentaire ;
- favori.

Les icônes doivent servir la compréhension rapide. Elles ne doivent pas être purement décoratives.

## 3.6 Illustrations et visuels food

Chaque page peut intégrer un visuel food ou une illustration sociale.

Règles :

- style orange cohérent avec la marque ;
- illustrations humaines simples, chaleureuses, non réalistes ;
- images food appétissantes mais bien intégrées ;
- éviter les images trop sombres, trop saturées ou trop agressives ;
- les visuels doivent renforcer la fonction de la page.

Le burger / food splash sur la gauche est un motif récurrent. Il sert de repère visuel de marque et doit rester cohérent dans les pages principales.

# 4. Règles UX globales

## 4.1 Navigation principale

La navigation principale contient :

- Découvrir ;
- Groupes ;
- Avis ;
- Mes calls.

La partie droite contient :

- notification ;
- avatar utilisateur ;
- nom utilisateur ;
- niveau ;
- accès profil / paramètres.

L’onglet actif est signalé par :

- texte orange ;
- icône orange ;
- underline orange.

## 4.2 Structure récurrente des pages

Les pages principales utilisent généralement :

- un header / hero contextuel ;
- une zone principale d’action ou de consultation ;
- une colonne latérale droite avec statistiques, activité ou classement ;
- des cartes secondaires en bas pour l’historique, les favoris, les tendances ou les badges.

## 4.3 Actions principales

Les actions primaires doivent être orange, visibles et directes.

Exemples :

- Lancer un FoodCall ;
- Créer un groupe ;
- Lancer un vote ;
- Écrire un avis ;
- Créer un nouveau call ;
- Modifier le profil.

Les actions secondaires doivent être en bouton blanc avec bordure grise ou orange.

## 4.4 Gamification

FoodCall utilise une gamification légère.

Éléments présents :

- niveau utilisateur ;
- score de call ;
- réputation ;
- badges ;
- classements ;
- taux de réussite ;
- points communautaires ;
- statistiques personnelles.

La gamification doit aider à comprendre la fiabilité des utilisateurs. Elle ne doit pas devenir l’objectif principal du produit.

# 5. Composants récurrents

## 5.1 Header global

Présent sur toutes les pages.

Contenu :

- logo FoodCall ;
- navigation principale ;
- notification ;
- profil utilisateur.

Règles :

- hauteur constante ;
- fond blanc ;
- ombre très légère ;
- forte lisibilité ;
- espace suffisant entre les éléments.

## 5.2 Hero de page

Présent sur les pages principales.

Contenu possible :

- titre fort ;
- phrase explicative ;
- boutons d’action ;
- illustration ou visuel food.

Règles :

- le hero doit expliquer rapidement la valeur de la page ;
- ne pas surcharger le hero ;
- conserver une cohérence de style entre les pages.

## 5.3 Cartes statistiques

Utilisées pour afficher :

- scores ;
- moyennes ;
- taux ;
- classements ;
- progression ;
- badges.

Règles :

- chiffres grands et visibles ;
- labels courts ;
- pictogramme associé ;
- barres ou cercles de progression si utile.

## 5.4 Listes de restaurants

Chaque restaurant doit pouvoir afficher :

- image ;
- nom ;
- type de cuisine ;
- note ;
- nombre d’avis ;
- distance ;
- temps estimé ;
- tags éventuels ;
- action rapide.

## 5.5 Cartes de vote

Une carte de vote doit afficher :

- nom du groupe ;
- question ;
- temps restant ;
- participants ;
- options classées ;
- barres de progression ;
- nombre de votes ;
- pourcentage ;
- action de vote.

## 5.6 Cartes de call

Une carte de call doit afficher :

- restaurant recommandé ;
- utilisateur qui propose ;
- groupe concerné ;
- statut du call ;
- votes ou soutien ;
- résultat ;
- score final ;
- actions : détails, modifier, partager.

## 5.7 Cartes d’avis

Une carte d’avis doit afficher :

- restaurant ;
- note globale ;
- reviewer ;
- date ;
- texte d’avis ;
- critères détaillés ;
- actions : utile, commenter, sauvegarder, voir l’avis complet.

# 6. Pages présentes dans le prototype

## 6.1 Page Découvrir

### Objectif

Permettre à l’utilisateur de trouver rapidement où manger autour d’un point de départ.

### Contenu principal

La page Découvrir contient :

- un hero “Choisissez où manger, ensemble” ;
- un champ d’adresse de départ ;
- un filtre type de cuisine ;
- un bouton principal “Lancer un FoodCall” ;
- une carte interactive de Lille ;
- une liste de restaurants à proximité ;
- un bloc de vote de groupe en cours ;
- un bloc de réputation utilisateur ;
- une barre de statistiques globales en bas.

### Rôle UX

Cette page sert d’entrée principale dans le produit.

Elle doit répondre rapidement à la question :

> Où peut-on manger maintenant, autour de nous ?

### Éléments importants

- Carte géographique centrale ;
- restaurants proches ;
- distance et temps estimé ;
- lancement rapide d’un FoodCall ;
- rappel que l’expérience peut être individuelle ou collective.

---

## 6.2 Page Groupes

### Objectif

Permettre à l’utilisateur de gérer ses groupes, lancer des votes et suivre les décisions collectives.

### Contenu principal

La page Groupes contient :

- un hero “Organisez vos groupes facilement” ;
- des boutons “Créer un groupe” et “Inviter des amis” ;
- une colonne “Mes groupes” ;
- une carte détaillée du groupe sélectionné ;
- une adresse de départ du groupe ;
- des actions : lancer un vote, proposer un restaurant, gérer le groupe ;
- une carte “Vote en cours” ;
- des calls récents dans le groupe ;
- un historique des décisions ;
- un classement des membres ;
- une activité récente ;
- une carte d’invitation avec code et lien.

### Rôle UX

Cette page sert à organiser la décision collective.

Elle doit permettre de comprendre :

- dans quel groupe on se trouve ;
- si un vote est en cours ;
- quelles options sont proposées ;
- qui participe ;
- quelle décision est en train de se former.

### Éléments importants

- Statut du vote ;
- classement des options ;
- score de pertinence des calls ;
- historique des restaurants choisis ;
- facilité d’invitation.

---

## 6.3 Page Avis

### Objectif

Permettre de consulter, filtrer et publier des avis détaillés sur les restaurants.

### Contenu principal

La page Avis contient :

- un hero “Partagez vos avis, découvrez les meilleurs spots” ;
- des boutons “Écrire un avis” et “Ajouter un avis rapide” ;
- une colonne de filtres ;
- un bloc “Spots en tendance” ;
- des onglets : avis de la communauté, avis de mes groupes, avis de mes amis ;
- une carte restaurant mise en avant ;
- un détail des critères de notation ;
- une liste d’avis récents ;
- un classement des top contributeurs ;
- des moyennes communautaires ;
- une activité récente ;
- une liste des restaurants les plus commentés.

### Rôle UX

Cette page sert à aider la décision par la preuve sociale.

Elle doit permettre de comprendre rapidement :

- quels restaurants sont appréciés ;
- pourquoi ils sont appréciés ;
- quels avis sont fiables ;
- quels critères sont importants.

### Critères d’avis

Les critères visibles sont notamment :

- goût ;
- rapport qualité / prix ;
- ambiance ;
- service ;
- rapidité ;
- quantité.

## 6.4 Page Mes calls

### Objectif

Permettre à l’utilisateur de suivre ses recommandations, leur performance et sa réputation.

### Contenu principal

La page Mes calls contient :

- un hero “Faites les meilleurs calls pour votre groupe” ;
- des boutons “Créer un nouveau call” et “Lancer un call rapide” ;
- une carte “Call en cours” ;
- les métriques du call actif : participants, votes reçus, soutien, décision ;
- une liste “Mes calls récents” ;
- des filtres : tous, retenus, non retenus, en cours, brouillons ;
- un score par call ;
- un score global de call ;
- un classement des top callers ;
- une activité récente ;
- des badges remportés ;
- des cuisines plébiscitées ;
- les meilleurs calls ;
- les restaurants souvent recommandés.

### Rôle UX

Cette page transforme la recommandation en mécanique sociale.

Elle doit permettre de comprendre :

- quels calls ont été utiles ;
- quels restaurants l’utilisateur recommande souvent ;
- quelle est la fiabilité de l’utilisateur ;
- comment progresser dans la communauté.

### États de call

Les états visibles peuvent être :

- call en cours ;
- retenu ;
- non retenu ;
- brouillon ;
- en attente d’évaluation.

# 8. États et feedbacks à prévoir

## 8.1 États vides

Chaque page doit prévoir des états vides.

Exemples :

- aucun groupe rejoint ;
- aucun avis publié ;
- aucun call créé ;
- aucun restaurant favori ;
- aucun vote en cours.

Chaque état vide doit proposer une action claire.

## 8.2 États de chargement

Prévoir :

- skeleton cards ;
- loaders discrets ;
- placeholders pour images ;
- feedback sur les boutons d’action.

## 8.3 États d’erreur

Prévoir :

- erreur de géolocalisation ;
- restaurant indisponible ;
- vote expiré ;
- invitation invalide ;
- erreur réseau ;
- action impossible.

Les erreurs doivent être expliquées simplement et proposer une action de récupération.

## 8.4 États de succès

Prévoir :

- avis publié ;
- call créé ;
- vote lancé ;
- groupe créé ;
- invitation copiée ;
- restaurant ajouté aux favoris.

Les succès doivent être visibles mais non intrusifs.

# 9. Règles de cohérence produit

## 9.1 Cohérence des données

Les mêmes entités doivent rester cohérentes entre les pages.

Exemples :

- Thomas doit conserver son niveau, son score et son identité ;
- les restaurants récurrents doivent garder leurs notes et catégories principales ;
- les groupes doivent garder leurs noms et nombres de membres ;
- les scores de call doivent être cohérents avec la page Profil.

## 9.2 Cohérence des actions

Une action doit avoir le même sens partout.

Exemples :

- “Lancer un vote” doit toujours ouvrir un processus de vote ;
- “Créer un call” doit toujours concerner une recommandation forte ;
- “Écrire un avis” doit toujours ouvrir la rédaction d’un avis ;
- “Partager” doit toujours créer ou copier un lien partageable.

## 9.3 Cohérence des statuts

Les statuts doivent être uniformisés.

Statuts de vote :

- vote en cours ;
- vote terminé ;
- aucun vote en cours ;
- décision en attente.

Statuts de call :

- en cours ;
- retenu ;
- non retenu ;
- brouillon ;
- à retravailler.

Statuts de contribution :

- validé ;
- pertinent ;
- excellent ;
- nouveau ;
- populaire.

# 10. Synthèse

La direction artistique de FoodCall repose sur une interface claire, premium et sociale.

Les piliers visuels sont :

- blanc dominant ;
- orange comme couleur d’action et d’identité ;
- cartes arrondies ;
- ombres légères ;
- illustrations food et sociales ;
- navigation simple ;
- statistiques lisibles ;
- gamification modérée.

Les piliers produit sont :

- découvrir des restaurants ;
- décider en groupe ;
- voter ;
- recommander via des calls ;
- publier des avis détaillés ;
- construire une réputation communautaire.

FoodCall doit donner l’impression d’un produit social utile, rapide à prendre en main et suffisamment riche pour devenir une habitude dans les décisions de repas entre amis, collègues ou groupes d’étudiants.
